# Web 管理端认证对齐两段式（sms-login 发 ticket + enter-tenant 换令牌）

## Context

移动端已改为两段式（全局账号级 ticket → enter-merchant 换令牌），但 Web 端 `/admin-api/system/auth/sms-login` 仍是旧模型：要求登录前携带 tenant-id 头、按"当前租户关联"直接签发 default 令牌——与全局账号多租户模型矛盾（多主体商户在 Web 登录页无法预知租户，且新账号无任何租户头可用）。本次将 Web 短信登录对齐为同一套两段式；平台管理员账号密码登录（tenant 头 + default 令牌）保持不变。

## 目标契约（Web 管理端）

| 接口 | 变化 |
|---|---|
| POST /admin-api/system/auth/sms-login {mobile, code} | **重写**：消费验证码 → getOrCreate 全局账号 + 状态校验（不碰租户/关联）→ 颁发 Auth-Ticket（复用 `AuthTicketRedisDAO`，同一 30m 配置）；不再要求 tenant 头、不再直接发令牌 |
| POST /admin-api/system/auth/enter-tenant {tenantId}（**新增**，头带 Auth-Ticket） | ticket 校验 → `validateSwitchContext` 三重校验 → **default client** 令牌（Web 会话）→ ticket 一次性消费 |
| GET /admin-api/merchant/org/mylist | 已支持 Auth-Ticket 头，Web 前端复用（选主体数据源） |
| POST /login（账号密码）| 不变（平台管理员流程，tenant 头） |
| /send-sms-code、/refresh-token、/logout、/accessible-tenants、/switch-tenant | 不变（send-sms-code 的登录场景本就无存在性前提） |
| /register、/reset-password、/social-login | 原样保留（Yudao 原生，不动） |

## 改动文件（全部在 system 模块）

- `controller/admin/auth/vo/AuthTicketRespVO`（新）：{accountId, ticket, ticketExpiresTime}（遵循端内 VO 规范，不跨端引用 app 包 VO）；`AuthEnterTenantReqVO`（新）：{tenantId @NotNull}
- `AdminAuthService`：smsLogin 返回类型改 `AuthTicketRespVO`；新增 `enterTenant(String ticket, AuthEnterTenantReqVO)`
- `AdminAuthServiceImpl`：
  - `smsLogin` 重写为账号级（useSmsCode 消费 → getOrCreateAccountByMobile → validateAccountEnabled → authTicketRedisDAO.create → 返回 ticket）；删除旧的"租户头 + getValidRel + 直接发令牌"路径
  - `enterTenant`：镜像 `AppAuthServiceImpl.enterMerchant`（L107-125），仅 client 换 `CLIENT_ID_DEFAULT`，登录日志复用 createLoginLog
- `AdminAuthController`：sms-login 响应类型更新；新增 `/enter-tenant`（@PermitAll + @RequestHeader("Auth-Ticket")）
- `application.yaml` ignore-urls 精确追加：`/admin-api/system/auth/send-sms-code`、`/admin-api/system/auth/sms-login`、`/admin-api/system/auth/enter-tenant`（**不加** `/login`——密码登录依赖租户头过滤，防止跨租户用户名串扰）

## 不变项

AuthTicketRedisDAO/RedisKeyConstants/AuthTicketApi、TokenAuthenticationFilter、移动端全部端点、商户自助 6 端点、平台审核接口、DDL/菜单。

## 验证

1. 新增 `AdminAuthServiceImplTest`（smsLogin=ticket 发放不碰关联；enterTenant 成功/无效 ticket/无关联不消费）+ 全量单测回归 + `mvn package`
2. dev 冒烟：商户手机号 Web 短信登录（无 tenant 头）→ ticket → mylist 选主体 → enter-tenant 得 default 令牌 → 令牌调 `/admin-api/system/auth/get-permission-info`（tenant 头）可用；**平台 admin 密码登录回归**；ticket 重放拒；跨租户 enter-tenant 拒。冒烟数据清理。

## 风险与说明

- Web 短信登录响应结构变更（原直接返回令牌），前端需按两段式对接；账号密码登录不受影响。
- 平台管理员若也用短信登录（手机号 18818260272 有租户 1 关联），同样走两段式后 enter-tenant(1) 即可。
